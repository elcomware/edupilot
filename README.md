# EduPilot

> **Finance is EduPilot's first commercial domain—not EduPilot's architecture.**

EduPilot is a modular school operating system. Finance is the first domain built and sold, on top of a reusable **EduPilot Core** that owns institutional concepts: organisations, campuses, academic structure, people, users, roles, permissions, workflows, documents, notifications, audit, settings, import/export and backups.

Every later domain — Admissions, Academics, HR, Attendance, Library, Transport, LMS, Parent Portal — plugs into the same Core instead of replacing it.

## Delivery

| Mode | Description |
|---|---|
| A — Standalone Desktop | Wails 3 host, React + TypeScript UI, Go backend, SQLite. One computer, offline-first. Build first. |
| B — School Site Server | Go backend owning the database; desktop clients over the school LAN. |
| C — EduPilot Cloud | Go API + PostgreSQL + object storage, fed by the durable outbox. |

## Layering

```text
React
  ↓
Frontend Gateway
  ↓
Transport (Wails today, HTTP later)
  ↓
Application Services
  ↓
Domain
  ↓
Repository Interfaces (ports)
  ↓
Infrastructure Adapters (SQLite / PostgreSQL)
```

Dependencies always point inward. The domain must not know about React, Wails, SQLite, PostgreSQL or HTTP.

## Money, IDs, immutability

- Money is **integer minor units plus currency** — never floating point.
- Identifiers are **UUIDv7**. Business-visible numbers (e.g. `REC/LOME/2026/004521`) are separate, generated by the numbering engine.
- Posted financial records are **append-only**: correct with reversal, credit, void and repost. Never delete, never edit.
- **Debits must always equal credits**, always.

## Getting started

```bash
task install     # install Go and frontend dependencies
task dev         # run the desktop app with hot reload
task check       # lint + unit + invariant + migration tests
task build       # production frontend + Go + Wails installer
```

See `ARCHITECTURE.md` for the governing principles and `docs/adr/` for the decisions behind them.
